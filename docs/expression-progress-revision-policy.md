# 表达课程修订与学习进度规则（待确认）

## 当前问题

`session-service.js` 的 progress() 按 lessonId 跨版本合并完成记录，没有比较教学内容。同编号单元即使新增或替换练习，也可能直接显示已完成。

现有未完成会话固定在原发布版本，继续学习不应切换其中的题目；此行为已有测试，必须保留。

## 建议规则

1. 课程名称、简介、单元标题等展示文案变化：继承进度。
2. 单元的练习、答案、学习目标、前置技能、教学技能或音频内容变化：作为新版教学内容，不自动继承旧版完成状态。
3. 仅音频存储位置变化、实际内容哈希不变：继承进度。
4. 新增单元：未开始；移除单元：不计入新版分母，历史记录保留。
5. 未完成的旧版学习继续使用原版本。目录同时说明存在旧版学习记录，避免把旧版进度和新版进度混为一谈。
6. 历史错题和复习记录保留其原版本；不能无提示混入新版统计。

## 实现范围

在服务端集中计算教学内容指纹，目录和首页共用结果。根据练习内容与其引用音频的内容哈希比较，而非仅依靠手工增加 contentVersion。不迁移、不重写历史会话和答题记录。

指纹字段清单需要显式定义，不能简单比较整份课程 JSON：否则只改简介也会误判为教学变化。音频引用须按 assetId 解析到 sha256，避免音频字节变化但课程 JSON 未变化时误继承。

## 验收条件

- 只改简介或标题，完成率保持。
- 修改一个单元的练习或音频，仅该单元不继承新版完成状态。
- 新增单元增加新版分母，旧完成记录不丢失。
- 移除单元不删除其会话、错题及历史发布版本。
- 中途修订课程，旧会话恢复的版本和位置保持。
- 首页与目录采用同一份服务端统计。
- 账号 A 的所有统计、错题和旧版信息对账号 B 不可见。

所有验证使用临时数据库、独立端口和合成账号，不调整真实学习记录。
