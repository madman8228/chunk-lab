## 2. 产品定义

### 2.1 Product Goals（3 个正交目标）

1. **主次归位**：首页第一屏的主角是「我自己的课程」与「下一步该做什么」；所有回顾性/统计性信息（打卡、计数）降为一行可扫读的轻量信息，不与可点动作争夺视觉权重。
2. **动作可发现**：用户打开首页就能在 1 次点击内进入「继续学 / 开始某课 / 待复习 / 错题本 / 添加课程」中的任一高频动作，入口不再被大数字卡稀释。
3. **视觉与既有规范一致**：全部图标使用项目现有 `Icons.svg(name)`（禁止 emoji/Unicode 字符当按钮），计数口径复用 `core.js` 单一实现，不新增第二套日历/进度实现。

### 2.2 User Stories

| # | As a … | I want … | So that … |
|---|---|---|---|
| US1 | 每天回来学习的用户 | 打开首页第一眼看到「继续 · 口语 3000 句 · 第 4 课」这样一条整行续学入口 | 0 思考就能接着上次的位置练 |
| US2 | 有多门课的用户 | 在「我的课程」里每门课看到**进度条 + 已学句数**，并有一个「管理 ›」入口 | 一眼判断哪门课落后，并能在需要时进课程管理页 |
| US3 | 刚导入新课的用户 | 在课程列表底部看到 `+ 添加课程`，未开始的课程显示 `开始` 药丸 | 导入的课不会在首页隐形，能立刻开学 |
| US4 | 需要安排今日学习的用户 | 在「今天要做」看到 `待复习 12 / 错题本 3 / 已熟练 N / 目标 3/20` 这几枚小药丸 | 不占地方地知道今天有哪些队列、练了多少 |
| US5 | 关心坚持度的用户 | 看到一行 `连续 6 天 · 本月打卡 12 天` 并可按需 `展开 ›` 看月历 | 打卡信息在但默认不占版面 |

### 3.3 需同步更新的现有测试（重要 · 不更新即变红）

|---|---|---|
| `E4 两张行动卡等宽（差<=2px）` | 场景 E | 药丸不等宽 → 契约应改为「药丸区间距一致 / 可换行且不溢出」 |

| `E5 计数区占满今日卡宽 >= 95%` | 场景 E | 药丸不占满整行 → 该判据作废 |
| `E6 数字与标签上下堆叠` | 场景 E | 药丸是**横向**「数字+标签」 → 判据反向 |
| `E7 数字横向居中 ±2px` | 场景 E | 药丸文字左对齐/自然流 → 判据作废 |
| `G1 已熟练计数出现在错题本右侧，值为 5` | 场景 G | 依赖「在错题本右侧」的 DOM 顺序 → 需按新布局更新 |

## 4. 验收标准汇总（可测）

1. 首页自上而下顺序为：顶部行 → 续学条 → 我的课程 → `+ 添加课程` → 今天要做 → 打卡行。
2. 计数区**不再**出现 32px 数字的三列等宽卡；呈现为小药丸行。
3. `待复习` / `错题本` 药丸可点且进入对应队列；计数 0 时禁用/置灰不可点。
4. `已熟练` 数字 == `stats.html#masteredCount`（逐字一致）。
5. 课程行含进度条与 `已学 N 句`；**整行可点**（`cursor:pointer` + hover/focus-visible，可 Tab 聚焦）进入该课；**行尾无按钮**；标题右侧有 `管理 ›`（→ `decks.html`）。
6. `+ 添加课程` 为虚线整行按钮，点击进入导入流程。
7. 打卡行默认收起，点击 `展开 ›` 显示月历（同一份 `.cal-grid`）。
8. 360 / 390px 宽无横向溢出；可点元素（药丸/课程行）点击区域 ≥ 44×44。
9. 全部新增图标为 `Icons.svg(name)` 输出的 `<svg>`，无 emoji/Unicode 字符充当按钮。
10. 无 `pageerror`。
11. 药丸行为**四枚**且顺序为 `待复习` → `错题本` → `已熟练` → `目标`（已熟练在错题本右侧）；续学条指向的课**不**在课程列表重复出现。

## 5. 裁决结论（老板 2026-09-25 已拍板）

### 裁决 1 · 计数区形态 = 药丸（替代三列等宽大卡）✅ 已裁决

- **背景**：设计稿=三枚小药丸；现状=三列 32px 大数字卡；老板此前已两次明确否定大卡（原话：「为什么要把 待复习，错题本，已熟练，夹到中间显示」「加一个已掌握的句子数量显示到错题本右侧即可」）。
- **裁决**：**采用设计稿药丸形态，替代当前三列等宽卡。** 与老板两次反馈一致，且符合「内容占主位、计数降级」目标。
