## Assumptions and decisions

1. “所有课程独立”指内容实体生命周期不依赖学习账号；制作审计、编辑权限、访问权限仍可关联操作者。独立存储不授权自动公开私人导入内容。新导入默认限制给导入者访问，管理员发布后才按公共策略可见；删除账号不会删除内容实体。
2. 保留单体、SQLite、现有素材文件库及协议 3 的 requestId 幂等队列。不开微服务、不引入第二个消息队列、不批量重编号课程/题目、不重写评分与会员系统。
3. 三个责任边界：内容发布、学习关系/记录、访问授权。课程库不依赖 user_change_seq；学习同步不携带正文。独立内容加载仍须满足访问控制，不能用共享缓存绕过会员/私人访问限制。
4. “只把课程改挂默认账号”“忽略 seq 回退”“清空缓存重拉”不能建立该边界，均不采用。通过小范围前端兜底也无法修复旧数据归属。
5. 内容加载和个人同步分别返回状态。同步冲突时可以显示目录、详情及获准读取的内容；有成绩的练习暂不可提交，明确提示记录待恢复，不显示虚假的进度。不另增无记录练习产品模式。

## Scope

覆盖平台句子课、图文课、教材/单词本及现有个人导入课程的持久化边界；接通 discover/my-learning、decks.html、main.html 原生学习、wordbook.html 和个人导入/制作入口。复用现有课程格式及播放器。完成迁移 dry-run/apply、旧分区隔离恢复、隔离升级和离线测试、现场部署操作清单。

## Out of scope

不新增课程、不重生成媒体、不修改教材教学内容；不删除任何真实账号/旧表/原文件，不将默认账号历史成绩自动归给登录用户；不扩大离线许可，不整库预缓存，不重做 UI 风格；不自动提交、推送、部署或执行真实迁移。

### Personal vocabulary books: storage boundary decision (2026-10-21)

Read-only audit found that `personal_wordbook_versions` is still the remaining account-owned content source. It currently combines immutable vocabulary packages/revisions with creator scoping; it is not learning progress. Learning state is already separate in `user_entity_rows` (`vocabularyResume` / `vocabularyBrowseResume` / `vocabularyStudySummary`) and vocabulary event/progress tables. The dedicated personal-wordbook archive is exported alongside the account backup, so migrating content must not silently drop or reinterpret that archive.

Decision for implementation: store each authored wordbook as an immutable independent-library release using the existing generic `course` storage kind, with an explicit versioned `contentFamily: "vocabulary-book"` envelope. This avoids rebuilding SQLite tables solely to expand CHECK enums; the existing `course` storage kind is the generic immutable content container, while domain readers remain vocabulary-specific. Use the existing private-by-default ACL for creator access. Preserve the original stable book/item/unit IDs inside the envelope during compatibility migration so vocabulary history and resume keys remain interpretable; map legacy source with a `course` mapping ID namespaced as `wordbook:<legacyBookId>` to prevent collision with sentence-course IDs. Adapt the existing wordbook APIs to resolve that alias and read its release through the library ACL; do not send vocabulary packages through sentence `readBatch`.

Migration must copy every immutable historical package version in order, preserve source JSON and all referenced asset bytes/hashes, and be idempotent by `(source user, namespaced source ID, source version/hash)`. Current rows remain untouched until a separately approved production run. For duplicate legacy copies owned by different accounts, do not deduplicate based on title/content: each source is private and its sharing intent is unknown. Keep the account-scoped archive contract available during transition; export must clearly include legacy records until verified independent-library backup/restore covers these releases. Before production cutover, audit orphan progress/event references and ensure their legacy IDs resolve through an account-scoped mapping without copying learning state into content storage.

Why not use a new `vocabulary-book` enum right now: it would require table rebuilds because both `course_contents.kind` and the legacy mapping `source_kind` are CHECK-constrained and referenced by foreign keys. An explicit envelope plus namespaced existing mapping is the smaller reversible change with the same storage/ACL separation. Reconsider a schema-level domain enum only if typed catalog queries later require it.

## Risks and rollback

- 最大风险是旧 ID 冲突、私人内容误公开、遗漏评分/备份旧路径、旧 pending 被重复执行。以来源映射、权限不扩展、网络/持久化断言和升级夹具验证，不能仅查代码字符串。
- 内容库与学习数据分离消除课程被账号绑住，但不能消除真正的数据库历史回滚或跨设备并发，身份/seq保护继续保留。
- 真实迁移顺序：冻结相关内容写入→一致性 SQLite 备份及素材/浏览器导出验证→核对 manifest→应用新增内容与映射→部署匹配前后端并更新缓存→现场验收。未完成迁移不激活新格式。
- 无新写入前可回退代码及指针；已有新格式写入后，禁止直接回滚到可写旧协议。暂停写入并保留新内容/回执/学习数据，按恢复清单处理；不能用旧数据库快照覆盖新增记录。
- 若发现实质契约矛盾，标记 needs-planning 并列证据与单个决策；不要悄悄把个人课程永久留在旧存储后宣布完成。

本清单只规定未来如何演练。当前没有指定真实数据库、备份目标、浏览器分区和账号的逐项批准；不得用默认 `server/data` 或账号 37 运行迁移/激活，不得因此停止或切换 live 服务。

3. **导出并核对浏览器分区。** 对指定 UID 从正确 origin 导出完整 owner 分区及账号作用域 localStorage，记录浏览器确认水位与待提交队列；单独核对 Cache API 中未随分区 JSON 导出的媒体。以新建文件名保留原件，禁止清空/改名原分区。浏览器导出或 Cache API 资产缺失、pending 存在、UID/owner 不一致，都停止而不是猜测重放。
4. **只读生成、人工审阅清单。** 指定同一只读数据库和一个此前不存在的 manifest 文件：`node scripts/migrate-independent-course-library.cjs --db <绝对SQLite路径> --write-manifest <新manifest路径>`。审阅来源摘要、每个旧→新 ID、课/题数量、素材 hash、重复与缺失、学习引用映射及 ACL；任何来源/权限/身份/学习归属不明须先解决。应用前数据库源摘要必须仍完全匹配。
5. **配对审计并再次确认水位。** 执行 `node scripts/audit-browser-course-backup.cjs --browser-backup <分区备份JSON> --course-manifest <manifest路径>`。任何 blocker、未归属引用、浏览器独有媒体、待发送/已发送未确认操作、确认缓存序号与服务端当前水位不一致，均为硬停止条件；不得清空队列或把其他账号记录复制过来。
6. **隔离演练，再按清单应用。** 先在新分配临时数据目录和隔离端口完成完整迁移、学习保存、重启/断网、备份恢复和回退演练。只有源备份可恢复、manifest 摘要未变、内容/ACL/引用匹配且写入冻结仍有效时，才在批准窗口运行 `node scripts/migrate-independent-course-library.cjs --db <目标SQLite绝对路径> --apply-manifest <已审阅manifest路径>`。随后逐账号运行激活预览：`node scripts/activate-learning-data-format.cjs --db <目标SQLite绝对路径> --course-manifest <manifest路径> --browser-backup <分区备份JSON> --uid <明确批准的UID>`；核对结果、确认 seq 和所有旧映射。只有该 UID 的所有闸门通过、该账号单独授权并批准切换时，才额外显式加 `--apply`；每次只处理一个 UID。
7. **匹配部署与逐项验收。** 同一变更窗口部署兼容的前后端静态构建；确认 `/api/learning-data/format` 身份与格式头一致，课程目录/正文通过独立 ACL 读取；答题只改变个人 seq、不改变课程 release；学习快照/导出/outbox 不含正文或媒体。验证加入、刷新/新浏览器进程、断网排队、同 requestId 重连只应用一次、其他账号不能读取私有内容。保留前后端构建 hash、manifest/备份 hash、UID、水位、事件计数与审计日志。
8. **失败回退边界。** 在任何真实应用/激活前，失败即停止，保留原数据库/浏览器分区，修复后从只读预览重来。应用后但尚无新格式学习写入时，仅可按已演练且经批准的回退流程恢复；激活并有新写入后禁止用旧数据库快照覆盖新增记录或回到可写旧协议，须保留新数据并向前修复。任何情况下不删除课程、浏览器原记录、旧表或备份。

**上线前必须另行确认：** 精确数据库与备份绝对路径、具体 UID、浏览器 origin/owner、每条来源冲突与未匹配学习记录的归属、每门导入课的读取权限、未确认操作的逐条处理以及维护窗口。账号 37 不能由旧诊断材料自动推定为本轮目标。本 runbook 不是现场批准；目前也没有完成真实备份恢复演练、真实 manifest 审阅或生产部署。
