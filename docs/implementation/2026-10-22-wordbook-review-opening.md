# “继续审核”加载与通知

## 根因及处理

旧路径串行执行“详情 → 全量校验 → 再次详情 → 词条 → 当前图片”，其中详情本身已全量检查媒体；校验还会核对整个已发布目录。用户要等完这条链才看到内容，按钮没有独立忙碌状态，普通提示又会撑高内容区。

- 同次媒体核验共享已经读取的文件缓冲，不在音频任务一致性检查时重复读盘。缓冲仅属于该次核验，不跨请求复用音频内容。
- 后台审阅检查结果绑定完整课程包与实际文件身份、字节数、修改时间、变更时间等；只缓存最近 8 份结果。每次使用前重新检查文件状态与别名规则，核验前后文件变化则拒绝该结果。文件变更、丢失、替换或恢复均触发重新核验。
- 详情返回当前资源是否匹配已保存的验证修订号与指纹。匹配时不再提交自动全量校验；新导入或补齐素材后的课程仍自动检查，直接使用校验响应，不重复取详情。
- 显式校验与发布不使用审阅缓存，原有全量摘要、文件格式、授权、问题阻塞和发布并发检查保持不变。预览复用不等于重新审批，不更新原审核结论或草稿时间。
- 点击立即显示“打开中…”，同一课程的并发打开合并；过期响应不切换当前课程，失败后可直接重试。
- 操作提示固定在视口顶部，可关闭，不占布局高度；保留局部错误和技术明细的原有职责。

## 回归证据

- `e2e/admin-wordbook-open.test.cjs`：修复前捕获两次相同详情请求与一次自动校验；修复后只取一次详情、词条页及当前图片。覆盖按钮即时状态、重复点击、失败恢复、通知关闭、提示不推动列表，以及桌面/手机布局。
- `server/admin-wordbook-review-budget.test.js`：校验内每个媒体只读取一次；未变化预览不重复读取媒体；同尺寸篡改、素材删除/恢复使缓存失效；显式校验绕过缓存，发布拒绝被篡改的文件。
- 当时真实 96 词课程的只读测量：旧详情 480 次媒体读取，约 2.7 秒；新详情首次 288 次读取，约 0.18 秒，复用检查时 0 次媒体读取、约 0.03 秒。绝对耗时受文件缓存和机器负载影响，不是固定延迟保证。
- 原有后台发布、历史版本及教材生产验收在临时目录和独立端口执行。本次没有课程迁移、内容改写或自动上架。
