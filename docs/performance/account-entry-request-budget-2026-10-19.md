# 启动账号入口请求去重验收

## 根因与调整范围

首页账号入口监听 `cloud-config-changed`，该事件既表示配置变化，也表示保存通道初始化状态变化。之前每次通知都会重新读取配置和账号，即使入口标签已由同一会话的成功响应确认。

调整只在 `main.html` 的账号入口调度层：

- 同一服务地址、令牌、登录方式和是否要求登录均未变化时，后台状态通知不重新确认已显示成功的账号标签。
- 尚在进行的同会话后台入口确认共用任务；不同账号／地址不共用。
- 主动点击入口仍走 `refreshAccountEntry()`，重新向服务器读取配置和账号；没有给账号、权限或通用 API 增加 TTL 缓存。
- 读取失败清除入口确认标记；后续确认可恢复。旧任务的完成或失败不能覆盖新任务。

只记录入口是否已确认的会话键，不持久保存新的账号响应。账号资料本身变化但没有切换会话时，标签不会因保存通道状态通知重新读取；用户主动打开仍会得到新资料。这是消除无关刷新触发器的边界，不是权限缓存。

## 复现与回归

排障流程先给已有真实浏览器测试添加请求预算。修改前，启动配置请求超出两次的断言失败；此前记录为配置 4 次、账号信息 3 次。

新增 `scripts/account-entry-request-budget.test.cjs` 在全新 VM 中执行页面的真实账号入口函数，测试状态通知、主动验证、地址／令牌／登录方式变化、退出、共享失败、恢复、旧响应晚到。共享失败用例还暴露了 `return promise` 绕过外层异常捕获的问题，改为 `return await` 后所有调用均受同一异常边界保护。

隔离浏览器在新建临时数据库与合成账号下，首页启动及直接进入练习均观测到：

| 接口 | 改前 | 改后 |
| --- | ---: | ---: |
| GET /api/config | 4 | 2 |
| GET /api/auth/me | 3 | 1 |

这两个接口合计每次启动少 4 次请求；不意味着减少四次权限检查，实际业务 API 的服务端鉴权没有变化。剩余两次配置读取分别用于启动与入口确认，本轮保留独立职责，未改成长期缓存。

浏览器测试还覆盖主动打开个人中心，断言该动作仍发出配置及账号信息请求。测试用例接入已有 `e2e/membership-learning.test.js`，不访问运行中的用户数据目录或当前浏览器。
