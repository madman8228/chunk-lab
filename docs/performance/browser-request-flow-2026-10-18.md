# 浏览器请求流程验收与启动心跳去重

## 测试范围

在 `e2e/membership-learning.test.js` 已有的新建临时数据库、隔离端口和合成免费课程夹具中，新增独立测试账号与浏览器上下文。复用真实页面、API 和练习引擎，不操作用户当前浏览器，不清理真实课程或记录。测试结果保存于 `output/playwright/request-budget/workspace-flow.json`，不含凭据与课程内容。

流程覆盖：首页初始化、五次进度确认事件、首页闲置 12 秒、发现页、返回首页、聚焦刷新、直接进入免费练习、真实作答保存、退出、返回后确认事件。确认事件的独立测试使用浏览器派发；练习保存则通过真实输入和持久操作完成，二者不混为同一验证。

Service Worker 在该测试中禁用，以直接观察应用发起的 API 请求；本测试不是静态缓存收益测试或并发压测。12 秒闲置观测不能证明任意长时间完全不联网。

## 实测与优化

首次测量发现启动时 `/api/usage/heartbeat` 发出两次。新增断言后失败 `2 !== 1`。

原因是 `core.js` 完成云端初始化后直接发送心跳，而 `js/study-usage.js` 已有独立的访问统计调度。修改为：存在访问统计模块时，云端初始化复用其 `visit()`；没有该模块的旧入口仍保留原有直接发送行为。

这个处理在前端调度层统一心跳职责，而不是在服务端吞掉额外请求或给所有 API 增加缓存。已有的账号隔离、可见性／在线检查、请求进行中保护、健康状态每分钟频率与失败退避保留。初次失败不再由另一个入口立即绕过退避，代价是遵守原有重试等待，而非额外抢发。

修改后真实流程结果：

| 阶段 | 关键请求 |
| --- | --- |
| 首页初始化 | 访问心跳 1 次，原为 2 次 |
| 首页五次确认事件 | 无 API 请求 |
| 首页闲置 12 秒 | 1 次保存健康上报；没有目录、数据轮询、答题或学习时长写入 |
| 发现页确认事件 | 无 API 请求 |
| 首页聚焦 | 单词本、确认数据各读取 1 次 |
| 直接进入练习 | 访问心跳 1 次，原为 2 次；会话启动 1 次 |
| 真实答题 | 持久操作保存，不下载首页目录 |
| 退出练习 | 单词本与内容分片索引各读取 1 次 |

返回后的独立确认阶段还观察到一次学习时长尾部上报；该请求不是目录重复下载，不予删除。首页的保存健康上报也有独立用途，本轮保留。
