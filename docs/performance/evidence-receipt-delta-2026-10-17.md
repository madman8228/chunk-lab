# 长历史答题回执增量传输

日期：2026-10-17。实施范围：日常答题回执，不是首次同步历史分页。

## 行为与兼容

- 本地仍保留完整已确认学习证据；掌握判定、复习安排、统计逻辑不变。没有截断、删除或迁移历史记录。
- 支持 WebCrypto 的客户端，在本题已有至少31条证据时，使用 Accept 显式发送本地已确认序号。短历史和其他操作继续使用原回执格式。
- 服务端仅在序号连续、答案事件唯一、完整历史为32～5000条且不超过512 KiB时，尝试只发送新增证据与前后 SHA-256 摘要。替换后的 JSON 必须比原统计项更小。
- 客户端校验旧历史摘要、条数和序号，插入新事件，按原规则排序，再校验新摘要，最后走原有原子缓存提交与队列退休流程。离线迟到的事件不直接追加到末尾。
- 无密码学支持、不一致的历史、多设备序号缺口、损坏回执、存储失败或并发提交冲突，均保留完整读取回退路径。账号切换时拒绝应用旧账号响应。
- 旧客户端不请求此格式；旧服务端返回完整回执时新客户端仍能处理。GET回执恢复路径和数据库保存的 canonical 回执仍保持完整，不存储增量替代品。
- 此次只改变网络投影，没有新增数据库结构。与上一轮回执压缩存储的版本兼容要求是两回事；发布/回滚仍须保留上一轮存储解码器。

## 自动测量

使用临时数据库和隔离端口，经真实 HTTP 写入365天、每天20题，包括每天一道热点复习题、续学和结算，总计8030次写操作。没有使用真实课程或用户记录。

| 测量项 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 第365天热点答题回执，解压正文 | 122,320 B | 11,855 B |
| 同一回执，gzip传输正文 | 6,076 B | 1,942 B |
| 全年全部写回执，解压正文合计 | 82,986,346 B | 63,007,782 B |
| 全年全部写回执，gzip正文合计 | 11,761,157 B | 11,020,155 B |
| 首次完整快照，解压正文 | 6,292,019 B | 6,292,019 B |
| 写请求数 / 上传正文总量 | 8030 / 5,727,877 B | 8030 / 5,727,877 B |

热点单次解压正文减少约90.3%，gzip正文减少约68.0%；混合操作全年gzip正文减少约6.3%。不代表所有答题都能减少68%的流量。短历史避免增量证明开销；普通低频题在此模型中保持完整证据传输。

以上是HTTP正文，不含TLS、请求头等网络开销。序号放在Accept请求头，新增少量头部字节未计入上传正文。时间戳导致gzip结果有少量波动。

每个检查点把模拟客户端重建的每题完整证据与服务端全量快照逐项对比；30、100、365天均一致，计数和SQLite完整性检查通过。
