# 历史回执存储减量：无迁移、无损读取

日期：2026-10-17。

## 已实施

新写入回执不再在两个表中重复保存完整结果：

- `user_operation_receipts` 保留唯一完整结果。较大的 `changes` 和 `operation.stat` 合并做无损 gzip-1/base64 存储；请求编号、序号、结果类别和其他 `operation` 元数据仍为可直接查询的 JSON。
- `user_operation_events` 保留原有事件编号、事件哈希和操作编号，`result_json` 改为引用同账号的原始回执。引用与原始回执、学习记录在同一个现有事务内提交。
- HTTP 返回值不变：正常保存仍直接返回原始完整内存结果，重试或 GET 回执时解码还原。同一事件换请求编号重试仍返回原序号和原始 canonical delta，不生成新的学习事件或重新计算旧结果。
- 旧明文回执/事件照常读取，读取不改写它们。无 schema 变更、无新表、无旧记录迁移、无历史清理。

后端源码：`server/services/operation-receipt-storage.js`、`server/services/operations.js`。本轮没有实现学习历史懒加载或改变网络保存协议。

## 安全和成本限制

- 保留请求哈希与事件哈希校验；重复编号但不同内容仍拒绝，账号查询仍绑定 user_id。
- 引用缺失、回执损坏、未知编码或长度不一致时拒绝重放，绝不将其猜测为“未执行”后再次写入。
- gzip 自带校验；解压同时限制实际输出大小。伪造较小声明长度的大解压数据也会拒绝。
- 同步压缩限于原始回执总长和压缩块均不超过512 KiB，使用 level 1；小于1 KiB或压缩后没有节省时保留明文。超大课程导入不尝试同步压缩，避免阻塞事件循环。超限的大回执仍可能增长，不能宣称所有未来数据都固定压缩率。
- 字符串、中文、emoji、完整历史证据都无损还原，没有截断。
- 单词本恢复查询使用的 `operation.action/bookId/sessionId`、恢复归档读取的 `seq` 保持可查询，不需要修改它们的 SQL。

## 365天自动复测

沿用上一轮相同模型：每天20题、约10%首次答错，分别正常轮转与每天复习同一热点题。每场景7,300次答案、365次续学、365次结算；隔离数据库和端口，未使用生产数据。主程序通过实际 HTTP 接口写入。

存储量单位为十进制 MB。两类回执存储正文是数据库 `result_json` 的实际存储字节合计：优化前为明文JSON，优化后包含压缩内容的base64和事件引用，不是解压后的历史内容大小。

| 场景 / 天数 | 回执正文优化前 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 正常轮转 / 30 | 4.16 MB | 0.99 MB | 76.2% |
| 正常轮转 / 100 | 18.70 MB | 3.68 MB | 80.3% |
| 正常轮转 / 365 | 146.12 MB | 18.80 MB | 87.1% |
| 热点复习 / 30 | 4.74 MB | 1.02 MB | 78.5% |
| 热点复习 / 100 | 24.90 MB | 3.87 MB | 84.5% |
| 热点复习 / 365 | 227.32 MB | 21.20 MB | 90.7% |

| 一年后现场占用（数据库+WAL+SHM） | 优化前 | 优化后 |
| --- | ---: | ---: |
| 正常轮转 | 180.47 MB | 50.79 MB |
| 热点复习 | 262.36 MB | 53.77 MB |

现场占用还含索引、空闲页与日志，不能当成解压后JSON大小或真实部署的精确容量预测。没有运行 VACUUM 或清理旧数据库。

两种场景的答案/事件/回执行数均保持预期；完整启动快照解压后大小与上一轮一致：正常轮转6,165,159 B，热点6,292,019 B；SQLite quick_check通过。

全年全部写操作本机P95：正常轮转7.69 → 7.10 ms，热点13.71 → 12.89 ms。30/100天部分尾部读数有波动，运行期间也有独立回归测试；不能宣称生产CPU性能因此提升，也不能据此判断2核2G承载能力。主要已确认收益是存储量。

## 生效与回滚限制

**当前真实服务未重启、现有数据未迁移。** 更新后端后只对新回执生效，旧数据库不会立即缩小。已有回执和学习记录继续保留；若未来要改写历史数据，仍需另行明确授权及一致性备份。

新存储格式需要本轮解码器。不要让未更新的旧进程与新进程混用同一数据库写回执；发布时应协调替换写进程。回滚业务版本也必须保留兼容解码器，不能直接切回完全不认识新格式的旧后端。备份保留完整格式数据，不替代版本兼容要求。
