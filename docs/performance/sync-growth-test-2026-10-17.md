# 长期同步增长自动测试：30 / 100 / 365 天

测试日期：2026-10-17。结论：**现有增量与压缩有效，日常网络正文较小；更突出的问题是历史回执重复存储，以及单题历史证据反复传输。** 本轮只新增测试工具和报告，没有修改业务协议或真实数据。

## 自动测试方式与安全范围

- 每天20题、其中约10%首次答错；使用实际 HTTP 保存接口、实际判定后的事件归并、错题证据合并、续学位置和每日结算。
- 正常轮换：在1,000题池中固定轮转；热点复习：每天固定复习1题，另外19题从同一题池轮转。两场景各保存7,300次答案、365次续学位置和365次结算，共8,030次日常操作，另有一次合成课程初始化。
- 构造历史 occurredAt 时间戳加速回放，不是让程序真实运行365天。receivedAt 仍是本次测试时间。强制复习用于增长测试，不代表算法推荐的复习频率。
- 全新临时数据目录、隔离端口和合成账号；真实服务、原浏览器存储、课程、学习记录与备份没有改变。测试结束关闭隔离进程并移除临时数据库，保留测量报告。
- 小规模烟测后，完整执行两场景；再单独复跑热点场景以记录高频题单次响应。所有运行成功。
- 检查30/100/365天的答案总数、结算总数、完整每日记录、事件数量、保存序号连续性、增量不带未变课程、无重复 operation.stat，以及 SQLite quick_check。读取计划命中用户/请求编号和单题事件索引。
- 测试是单账号顺序操作，不是并发压测；没有测真实2核2G主机、浏览器解析/绘制/内存、会员自然过期或后台维护任务。不能据此宣称支持1万日活。

## 1. 正常轮换：网络正文大小

KB为十进制，压缩数据为服务端实际 gzip Content-Length；不含 HTTP 请求头、TLS 或重传。

| 指标 | 30天 / 600题 | 100天 / 2,000题 | 365天 / 7,300题 |
| --- | ---: | ---: | ---: |
| 一次普通正确答案上传正文 | 537 B | 538 B | 537 B |
| 该次保存响应：解压后 | 2.85 KB | 4.97 KB | 13.64 KB |
| 该次保存响应：gzip正文 | 0.86 KB | 1.11 KB | 1.90 KB |
| 本地已最新，启动确认响应：gzip正文 | 0.43 KB | 0.62 KB | 1.28 KB |
| 本地落后一天，启动增量：gzip正文 | 2.27 KB | 2.78 KB | 4.68 KB |
| 无本地缓存，新设备完整启动：gzip正文 | 46.0 KB | 101.6 KB | 245.4 KB |
| 新设备完整启动：解压后 | 0.87 MB | 2.11 MB | 6.17 MB |

上行样本为正确题；答错时还上传该题合并后的错题证据，不能据此把所有答题请求都描述成0.5 KB。

正常轮换全年8,030次操作的上传正文累计5.49 MB，保存响应gzip正文累计10.92 MB；此累计不含测量用的启动读取、心跳、鉴权、图片或其他页面请求。每次答案仍是窄事件，而不是整份课程/账号档案上传。

## 2. 高频重复题：历史增长

补测记录每天第一题的实际保存响应。它在第30/100天是答错事件，因此上行另含错题记录；第365天为正确事件。

| 每天复习的同一题 | 第30次 | 第100次 | 第365次 |
| --- | ---: | ---: | ---: |
| 保存回执解压后 | 13.19 KB | 38.27 KB | 122.32 KB |
| 实际gzip正文 | 1.60 KB | 2.70 KB | 6.08 KB |
| 保留的历史证据数量 | 30 | 100 | 365 |

第365次回执中，该题统计行约111.4 KB。压缩降低了网络正文，但服务端JSON装配、客户端解压和处理仍面对较大的历史内容。

热点场景全年保存响应gzip正文累计约11.76 MB，新设备首次完整启动约246 KB；落后一天的增量约8.97 KB。**热点显著增加的是单题和服务器存储，不是把每次网络正文直接放大到122 KB。**

## 3. 数据库存储：本轮最明显的问题

| 场景 / 指标 | 30天 | 100天 | 365天 |
| --- | ---: | ---: | ---: |
| 正常轮换：两类历史回执JSON合计 | 4.16 MB | 18.70 MB | 146.12 MB |
| 热点复习：两类历史回执JSON合计 | 4.74 MB | 24.90 MB | 227.32 MB |
| 正常轮换：数据库+WAL+SHM现场占用 | 11.94 MB | 31.34 MB | 180.47 MB |
| 热点复习：数据库+WAL+SHM现场占用 | 12.49 MB | 37.44 MB | 262.36 MB |

“两类历史回执”指 user_operation_receipts.result_json 和 user_operation_events.result_json。两者都保存结果，结果含当时的完整增量；单题证据和累计 daysLog 在后来回执中再次出现，形成增长放大。

- 365天正常轮换：两类回执146.12 MB；本报告统计的其他JSON行合计约9.17 MB。
- 365天热点复习：两类回执227.32 MB；其他JSON行合计约9.37 MB。
- JSON字节合计是逻辑载荷大小，不是SQLite表精确物理占用；数据库现场占用还含页面空闲、索引、WAL和SHM，不能与JSON数值直接相减后归因。
- 这是单个合成账号的特定高频使用模型，不能线性当作真实全部用户的容量预测。但足以确认回执存储应优先审查。
- 为防止离线重试重复写入，**不能按天直接删除幂等编号、哈希、序号和去重依据**。后续应研究保留这些安全依据、避免重复存放完整结果，或通过兼容格式重建需要的回执；不是清空历史学习记录。

## 5. 建议顺序

1. **先处理历史回执的存储放大**：保留幂等与恢复能力，减少两表及跨次回执中重复的完整JSON。先做兼容设计与失败恢复测试，不直接删除旧回执。
2. **再拆日常学习状态与历史证据传输**：日常操作只下发必要状态/新增证据，详细历史在查看时读取。必须保持掌握判定、统计重建、版本重置和多设备合并正确。
3. **最后评估新设备首屏轻量投影**：本地缓存命中的增量已很轻，主要是新设备完整历史装配与解析有增长。无需为了节省几百字节破坏可靠保存。

本轮没有实施上述架构改动。新增可重复运行的自动测试工具，无需用户手工点击或造数据。
